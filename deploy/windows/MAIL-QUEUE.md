# TXT / CSV 邮件轮询队列

入口：`/s/mail-queue`，仅管理员可访问。

1. 添加 QQ、谷歌、163、126 或 Outlook 发件账号。同类型可添加多个账号。
2. 在“渠道 → 电子邮件”保存主题和正文，推荐使用触发式邮件模板。
3. 上传 UTF-8 TXT，每行一个邮箱，无需表头；也支持逗号、分号（含中文标点）、空格或制表符分隔。或上传 CSV，至少包含 `email`，可选 `firstname`、`nickname`、`role`、`user_id`。
4. 选择本批发件账号，默认每 20 秒投递一封。本批默认上限 10 人。
5. 核对清理统计及收件人后启动。暂停后可继续；停止批次不可继续。

所有启用账号按选择顺序轮询，不按邮箱类型限制账号数量。一个批次包含 QQ1、QQ2、谷歌1 时，顺序即 QQ1 → QQ2 → 谷歌1 → QQ1。全局间隔可随时修改，最短 1 秒，最长 86400 秒。SMTP 自身处理耗时可能使间隔变长，不会为追赶进度集中补发。

TXT 示例（保存为 `客户邮箱.txt`，UTF-8 编码）：

```text
customer-a@example.com
customer-b@example.com
customer-c@example.com
```

TXT 和 CSV 都会去重、校验邮箱格式并应用本批人数上限，文件最大 10 MB，原始记录最多 50000 条。只有带角色信息的 CSV 能识别并排除群主和管理员；TXT 需使用已清理名单。上传只创建暂停批次，核对后点击开始才会发送。

凭据和队列位于租户运行目录的 `mail-queue`，不写入 Git。既有 Mautic 模板、个性化变量、退订及邮件统计通过原生 EmailModel 处理。已有退订联系人被跳过。频率规则或原生去重拦截也会跳过，不绕过原生发送规则。

SMTP 返回成功代表接收投递，不代表邮件最终到达收件箱。失败会暂停批次，失败记录不自动重试。进程若在投递中断开，该记录变为“待核对”；必须核对 SMTP 日志或收件箱后另建明确的补发批次，避免重复投递。正在投递的一封不能被暂停撤回。

谷歌和 Outlook 支持应用授权码或 OAuth 2.0 XOAUTH2；OAuth 需要自行取得已授权的客户端及刷新令牌，页面不是 OAuth 应用注册或交互授权向导。SMTP 的加密验证保持开启。

Windows 服务命令：`php bin/console yxhk:mail-queue:work --env=prod`。使用 PXYOPS 的 `Install-YxhkMailQueue.ps1` 安装租户后台服务；账号及权限沿用该租户的隔离服务账号。正式发布切换时会停止并重启邮件队列服务。

长期运行的后台进程会在每次投递前重新建立数据库连接，避免 MySQL 空闲会话过期影响下一封邮件。

营销发送前必须配置外部可访问的站点/退订地址。仅有 localhost 的部署可向自己试发验证正文和投递，但外部客户无法打开退订及跟踪链接。

定向回归：`php deploy/windows/Test-MailQueue.php`。脚本不连接 SMTP、不修改业务数据库。
